# Inventory API

A RESTful inventory management backend built with [Go](https://go.dev/), [Gin](https://github.com/gin-gonic/gin) and [GORM](https://gorm.io/) on PostgreSQL.

Each item has a UUID `id`, a `name`, a `stock` count and a `price`. The API supports:

- Full CRUD on items
- Pagination, sorting and filtering on the list endpoint
- Rate limiting with a token bucket (1 request/second, burst of 5)
- A database seeded with 20 sample items on first run

## Project layout

```
main.go        Item model, database + seed, handlers, rate limiter, routes
.env.example   template for local configuration
.env           your local configuration (git-ignored)
```

## Installation

Requires **Go 1.23+** and **PostgreSQL**.

```bash
git clone https://github.com/Nifilat/inventory-management-api.git && cd inventory-management-api
go mod tidy
```

### Database setup

1. Make sure PostgreSQL is running (macOS/Homebrew: `brew services start postgresql@18`).
2. Create the database and your local config:

```bash
createdb inventory
cp .env.example .env
```

3. Edit `.env` and set `DATABASE_DSN` for your machine. The connection string has this form:

```
DATABASE_DSN=host=localhost user=<your-user> password=<your-password> dbname=inventory port=5432 sslmode=disable
```

(With a default Homebrew install your user is your macOS username and no password is needed.)

On startup the server connects with this string, creates the `items` table with GORM `AutoMigrate`, and seeds 20 items if the table is empty. Check the data:

```bash
psql inventory -c "SELECT * FROM items;"
```

## Launch

```bash
go run main.go
```

The API is served at http://localhost:8080. Set `PORT` in `.env` to use a different port.

## Usage

| Method | Path             | Description        | Success | Errors        |
|--------|------------------|--------------------|---------|---------------|
| GET    | `/inventory`     | List items         | 200     | 400, 429      |
| GET    | `/inventory/:id` | Get one item       | 200     | 404, 429      |
| POST   | `/inventory`     | Create an item     | 201     | 400, 429      |
| PUT    | `/inventory/:id` | Update an item     | 200     | 400, 404, 429 |
| DELETE | `/inventory/:id` | Delete an item     | 200     | 404, 429      |

All responses are JSON. Errors look like `{"error": "Item not found"}`.

### Create an item

The `id` is generated by the server, so send only these fields:

```bash
curl -X POST localhost:8080/inventory \
  -H "Content-Type: application/json" \
  -d '{"name": "USB-C Dock", "stock": 12, "price": 79.99}'
```

```json
{"item": {"id": "2797e1c7-5246-459d-a0ab-24c0fc74766f", "name": "USB-C Dock", "stock": 12, "price": 79.99}}
```

`name` is required; `stock` and `price` must be 0 or greater.

### Get, update and delete

```bash
curl localhost:8080/inventory/<id>
curl -X PUT localhost:8080/inventory/<id> \
  -H "Content-Type: application/json" \
  -d '{"name": "USB-C Dock", "stock": 9, "price": 74.99}'
curl -X DELETE localhost:8080/inventory/<id>
```

`PUT` replaces `name`, `stock` and `price` (send all three).

### List items: pagination, sorting, filtering

`GET /inventory` accepts these optional query parameters:

| Param       | Description                                  | Default |
|-------------|----------------------------------------------|---------|
| `limit`     | Items per page, 1 to 100                     | 10      |
| `offset`    | Number of items to skip                      | 0       |
| `sort_by`   | `name`, `stock` or `price`                   | `name`  |
| `order`     | `asc` or `desc`                              | `asc`   |
| `name`      | Case-insensitive partial match on the name   | none    |
| `min_stock` | Only items with stock at or above this value | none    |

```bash
# second page of 5 items, most expensive first
curl "localhost:8080/inventory?limit=5&offset=5&sort_by=price&order=desc"

# items with "phone" in the name and at least 10 in stock
curl "localhost:8080/inventory?name=phone&min_stock=10"
```

Invalid values (for example `limit=0`, `sort_by=color`, `min_stock=abc`) return `400`.

The response includes the items and the paging used:

```json
{"items": [ ... ], "metadata": {"limit": 5, "offset": 5}}
```

### Rate limiting

A token bucket allows a burst of 5 requests, then refills 1 request per second. Requests over the limit get `429`:

```json
{"error": "rate limit exceeded"}
```

Try it:

```bash
for i in $(seq 1 8); do curl -s -o /dev/null -w "%{http_code} " localhost:8080/inventory; done; echo
# 200 200 200 200 200 429 429 429
```

## API documentation (Swagger)

With the server running, open http://localhost:8080/swagger/index.html for interactive docs where you can try each endpoint. The docs page is not rate limited.

The docs are generated from the annotations above each handler in `main.go` and committed in `docs/`. After changing an annotation, regenerate them:

```bash
go install github.com/swaggo/swag/cmd/swag@latest
swag init -g main.go
```

## Caching

`GET /inventory/:id` is cached in memory. `PUT` and `DELETE` clear the item's cache entry, so reads are never stale. The cache is emptied when the server restarts.
